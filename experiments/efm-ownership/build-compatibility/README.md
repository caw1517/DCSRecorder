# Read-only compatibility evidence

The installed DCS updated to **2.9.30.28536** during the session-control work.
The hold-only package correctly refuses preparation for this unvalidated build.
Reading the current WorldGeneral export table shows real changes:
ForcePosition moved from RVA `0x68d50` to `0x685e0`, and VectorVelocity from
`0x69310` to `0x68b90`. Changing just those addresses would not validate object
layout, integration, animation or engine access. Existing build guards remain.

This temporary helper captures only `.text`, `.rdata` and `.pdata` sections of
DCS.exe, WorldGeneral.dll, Sound.dll, AIFM.dll and CockpitBase.dll through the
existing read-only snapshot utility. It captures no writable `.data`, heap or
whole-process dump, invokes no DCS native methods and installs no memory hooks.
The resulting vendor code stays local and must not be committed or uploaded.

`045-Build-Compatibility.miz` contains one stock Hornet. The separate hook runs
the helper once when that diagnostic mission has a stock-Hornet player. Capture
goes under `Saved Games/DCS/Scripts/DCSRecorderBuildCapture/evidence-<pid>`.
Its `CAPTURED` message requires all fifteen expected image sections. A repeated
capture in the same process refuses to overwrite evidence. Close DCS before
installation or cleanup of the helper DLL.

Live check: start DCS, load the diagnostic, click Fly, wait ten seconds and exit
normally. Inspect `DCSR_BUILD_CAPTURE` in dcs.log and validate manifests and
section sizes before analyzing new addresses. This does not validate playback
compatibility; it supplies evidence for that work. Remove the additive hook
after capture while preserving the helper/evidence until DCS exits.

`audit.py` verifies section sizes/hashes and checks the existing native guards.
`candidate_profile.json` records offline address candidates only; it is not
consumed by any playback controller. `check_candidates.py` validates those
candidates against the captured byte guards and relevant table structure.

`HornetLayoutProbe` is the next read-only object diagnostic. Its generated byte
guards use this candidate map and reject other hosts. The actual SDK object
must independently match woAIPlane RTTI, the primary table and field-read guards.
It neither invokes native methods nor installs hooks or writes object fields.
The inherited EFM harness has its diagnostic moment pulse disabled for this
target; the mission player remains a stock Hornet. Logs go to the new module's
`bin/layout-logs` directory. A twenty-second mission-side position/velocity
trace supplies an independent comparison. Live field agreement is pending.
