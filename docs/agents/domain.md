# Domain docs

This project uses a single-context layout:
- CONTEXT.md at the repository root contains domain vocabulary.
- docs/adr/ contains architectural decision records.

Before exploring the codebase, read CONTEXT.md and ADRs relevant
to the area being investigated.

If these files do not exist, proceed silently. The domain-modeling
skill creates them when terms or decisions are resolved.

Use the glossary's vocabulary when naming domain concepts.
Note meaningful vocabulary gaps for domain-modeling.

Explicitly identify any proposal that contradicts an existing ADR,
including the ADR reference and the reason to reconsider it.
